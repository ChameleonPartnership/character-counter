How to Write Meta Descriptions That Earn Clicks

Published 13 July 2026. Updated 1 September 2026. Updated 17 September 2026.

Search snippets are small adverts for pages that already exist. The title has to identify the page. The description has to make the next click feel worthwhile. Character counts do not guarantee rankings, but they stop good copy being hidden by truncation.

Use the privacy-first character counter while you edit. Your text stays in the browser, and the limit bars give a quick check before you paste copy into a publishing tool.

Use length as a display constraint

A practical title tag target is around 50 to 60 characters. A practical meta description target is around 150 to 160 characters on desktop, with mobile snippets often showing less. Google may rewrite snippets, and pixel width matters as much as character count, but these ranges are still useful for drafting.

Write the page title first, not the keyword list. "Character Counter - Free Word and Letter Count Tool" is clear because it names the tool and the job. "Character Counter, Word Counter, Letter Counter, Text Counter" reads like a directory entry. It wastes trust before the searcher even lands.

For descriptions, make the page promise specific. "Use a privacy-first counter for characters, words, lines and reading time. Paste text, check platform limits and edit locally in your browser." That copy tells the reader what they can do and why this tool differs from a generic counter.

Write for the person comparing results

Searchers compare several blue links in seconds. A useful snippet answers three questions quickly: what is this page, who is it for, and what makes it worth opening? If the answer is only "high quality guide", the copy has failed. If it says "LinkedIn, X, SMS, app store and SEO limits in one table", the value is concrete.

Put the differentiator before likely truncation. For this site, "privacy-first" matters because text stays in the browser. For a pricing page, the differentiator might be "no contract". For a clinic page, it might be the location and service. The counter helps you see whether the phrase lands early enough.

Do not stuff every variation into the same field. Search engines and readers understand related language. A title that repeats "count", "counter", "counting" and "calculate" looks desperate. Use one natural phrase and spend the remaining characters on context.

Before and after examples

Weak title: "SEO Optimisation Guide for Better Search Engine Results and Higher Rankings". Better title: "Meta Description Examples for Higher Search Clicks". The better version is shorter, names the asset and avoids making a ranking promise the page cannot control.

Weak description: "Read our guide to learn everything you need to know about writing better metadata for your website pages." Better description: "Write title tags under 60 characters and meta descriptions around 155. See before and after snippets for tools, blogs and product pages." The better version includes numbers and use cases.

For an article, the description should not repeat the title. Use it to add a reason to click. If the title is "How to Shorten Any Sentence Without Losing Meaning", the description can promise the method: "Cut slow openings, weak verb phrases and filler while keeping numbers, tone and evidence intact."

Metadata checklist

Create metadata during editing, not after publication. The title and description often reveal whether the page has a strong enough angle. If you cannot describe the page in 155 characters without vague claims, the page itself probably needs a clearer promise.

Count both fields and record the final numbers in your content checklist. This is especially useful for teams using CMS templates where titles are combined with brand suffixes. A 52-character title can become 75 characters once the site name is appended.

Review live snippets after indexing. Search engines may choose different page text if the meta description does not match the query. That is normal. Your job is to provide a strong candidate that is accurate, specific and short enough to display cleanly in common results.

  • Put the page type and topic in the title.
  • Keep the title around 50 to 60 characters when possible.
  • Keep descriptions around 150 to 160 characters, with the strongest phrase early.
  • Avoid repeated keywords and generic claims.

Write different snippets for different page types

A tool page, article, product page and policy page should not share the same description shape. A tool page should state the task and the differentiator. An article should state the problem and the method. A product page should name the buyer, outcome and proof. A policy page should be plain and accurate.

For this site, the homepage description needs to say that the counter is privacy-first and browser-based. A blog article about SMS needs to mention segments and cost. A cheat sheet needs to promise the table of limits. Reusing one broad description across those pages would look thin because it ignores why each page exists.

Character counts make these differences visible. If every description comes out at 155 characters but none of them names a concrete benefit, the count is tidy and the copy is weak. Fit is only useful when the message is worth fitting.

Common metadata traps

The first trap is letting the CMS append a long brand suffix without checking the final title. "Meta Description Examples for Higher Search Clicks" is 50 characters. Add a 28-character brand suffix and the search result may hide the last phrase. Count the rendered title, not only the field you type.

The second trap is writing a description that promises too much. "Everything you need to know" sounds comprehensive but says nothing specific. "Before and after snippets for tools, blogs and product pages" is narrower and more believable.

The third trap is ignoring query intent. A searcher looking for a character counter wants the tool quickly. A searcher looking for meta description examples wants examples. Match the snippet to that intent, then count it.
